QO'LLANISH TARTIBI
------------------
Quyidagi promptlardan birini AI'ga yuboring. [QAVS ICHIDAGI] joylarni o'zingizning ma'lumotingiz bilan almashtiring.
AI javobida faqat tekshirilgan ma'lumotlar, source URL va ishonchlilik darajasi bo'lishi kerak.

1. KEYINGI MATCHNI TOPISH
--------------------------

Avval UEFA rasmiy saytini tekshir. Agar ma'lumot topilmasa, klubning rasmiy sayti va boshqa ishonchli sport manbalarini tekshir.

{

  "season": "",
  "match_id": "",

  "stadium": "",
  "stage": "",
  "source_urls": [],
  "confidence": 0.0,
  "notes": ""

8. FAQAT MATCHDAY RAQAMINI ALMASHTIRIB ISHLATILADIGAN PROMPT
-------------------------------------------------------------
Quyidagi promptda faqat MATCHDAY_NUMBER qiymatini almashtiraman. Masalan: 6 yoki 7.

PROMPT BOSHLANISHI:

UEFA Champions League [SEASON] mavsumining Matchday [MATCHDAY_NUMBER] bosqichidagi BARCHA matchlarni internetdan top.

Men faqat Matchday raqamini almashtiraman. Matchday [MATCHDAY_NUMBER] dagi barcha matchlar ro'yxatini to'liq chiqar. Hech bir matchni qoldirma.

Avval UEFA.com rasmiy fixtures/results va match centre sahifalarini tekshir. Keyin har bir match ma'lumotini kamida bitta qo'shimcha ishonchli manba bilan solishtir.

Har bir match uchun quyidagi ma'lumotlarni top:
- match ID yoki source match ID;
- matchday;
- season;
- date and kickoff time;
- UTC vaqt;
- home team;
- away team;
- stadium;
- city and country;
- stage;
- status: SCHEDULED, LIVE, FINISHED, POSTPONED yoki CANCELLED;
- home score;
- away score;
- extra-time score, agar bo'lsa;
- penalty score, agar bo'lsa;
- winner;
- goals va goal scorerlar, agar match tugagan bo'lsa;
- source URL’lar.

Match hali boshlanmagan bo'lsa score va goals qiymatlarini null yoz.
Match live bo'lsa hozirgi score va statusni yoz.
Match tugagan bo'lsa final score va barcha gollarni yoz.
Hech qanday ma'lumotni taxmin qilma. Topilmagan qiymatni null yoki UNKNOWN yoz.

Javobni quyidagi JSON formatida ber:

5. `all_matches_found` true bo'lishi uchun barcha rasmiy matchlar topilganmi?

9. MA'LUMOTLARNI DATABASE’DA XAVFSIZ SAQLASH PROMPTI
------------------------------------------------------
Yuqoridagi JSON ma'lumotlarini PostgreSQL bazasiga yozishdan oldin quyidagi xavfsizlik qoidalariga amal qil.

1. Ma'lumotni to'g'ridan-to'g'ri asosiy jadvalga yozma. Avval source_url, fetched_at, raw_json va parser_status bilan raw/import log saqla.
2. Faqat JSON validation muvaffaqiyatli bo'lsa asosiy jadvallarni yangila.
3. `MATCH_ID`, `source_match_id`, `GOAL_ID` va player identifier bo'yicha duplicate tekshir.
4. Yangi ma'lumot uchun INSERT, mavjud ma'lumot uchun faqat ishonchli va yangiroq qiymatlarni UPSERT qil.
5. Bo'sh yoki UNKNOWN qiymatlar bilan eski to'g'ri qiymatlarni almashtirma.
6. Barcha match, goal, player va prediction yangilanishlarini bitta PostgreSQL transaction ichida bajar.
7. Xato bo'lsa ROLLBACK qil; yarimta yuklangan ma'lumotni qoldirma.
8. Har bir import uchun sync_logs yozuvi yarat:
   - run_id
   - started_at
   - finished_at
   - source_urls
   - records_found
   - records_inserted
   - records_updated
   - records_rejected
   - status
   - error_message
9. Source URL va olingan vaqtni har bir import yozuvida saqla.
10. AI confidence 0.85 dan past bo'lsa, ma'lumotni `pending_review` holatida saqla va asosiy prediction modeliga qo'shma.
11. Score, goal eventlar soni va final result o'zaro mos kelmasa, matchni `needs_review` holatida qoldir.
12. Database paroli, API key va OpenAI key’ni JSON, prompt, Git yoki source code ichiga yozma. Ularni Railway environment variables’dan ol.
13. SQL query’larni string bilan birlashtirma; parameterized query va whitelist qilingan table/column nomlaridan foydalan.
14. Har bir importdan oldin mavjud recordlarni o'chirma. UPSERT ishlat, tarixiy ma'lumotni saqla.
15. O'zgargan eski qiymatlarni audit_history yoki raw payload ichida saqla.
16. Prediction faqat transaction commit bo'lgandan keyin ishga tushsin.

Tavsiya qilinadigan jadvallar:
- `sync_logs`: har bir internet qidiruvi va import holati;
- `raw_source_data`: o'zgartirilmagan source JSON/HTML va source URL;
- `match_events`: goal, card, substitution kabi eventlar;
- `audit_history`: eski va yangi qiymatlar;
- asosiy `matches`, `players`, `goals`, `teams`, `stadiums`, `predictions` jadvallari.

Database update natijasini quyidagi JSON formatida qaytar:
{
  "transaction_status": "COMMITTED|ROLLED_BACK|PENDING_REVIEW",
  "run_id": "",
  "records_found": 0,
  "records_inserted": 0,
  "records_updated": 0,
  "records_skipped": 0,
  "records_rejected": 0,
  "validation_errors": [],
  "source_urls": [],
  "database_tables_updated": [],
  "prediction_run_allowed": false
}
